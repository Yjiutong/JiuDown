## iPhone 美学图标（第三轮）

**需求**：侧边栏折叠开关 »、下载箭头、设置齿轮三个略缩图标不够美观，参考苹果 iPhone 设计美学重设计。

**实现**（main_window.py 图标系统，48px 设计稿整体缩放渲染）：
- **squircle 容器**：角部曲线 C(t)=(R(1-t)², Rt²)（隐式 √(u/R)+√(v/R)=1，等价控制点在矩形角点的二次贝塞尔）+ 同色系微渐变（顶 #4DCBC2 底 #32ADA5，中点 #39C5BB），inset=size*0.021 给抗锯齿留边，R=0.28*边长
- **SF 风格图形**：下载=45°箭头+竖杆+托线（圆头笔触 4.5px）；齿轮=6齿+轮身+中心孔；折叠=双雪佛龙（笔触 4px）；字形外框 21px（占容器 44%），统一笔触重量
- **选中态变体**：on_brand=True 仅绘白色图形（直接位于主色 pill 上，避免同色相叠）；齿轮孔选中态用 pill 主色 #39C5BB、未选中用渐变中点 #3FBEB5

**关键 bug 修复（squircle 十字形凹壁）**：初版用 Lamé 超椭圆 |x|^n+|y|^n=1 象限参数化 (R·cos^(2/n)t, R·sin^(2/n)t)，该曲线在贴边起点 (R,0) 处切线为**垂直**，与水平直边相接产生凹壁，垫底渲染证实呈"十字形"。且其对角点 (0.841R) 其实比圆弧 (0.293R) 更"空"——与 iOS 特征相反（旧测试的 arc_diag=0.707R 对比式本身也是错的）。改用 (R(1-t)², Rt²) 家族：起点水平切线/终点垂直切线（C1 连续，无折痕），对角点 0.25R 到角距离 0.354R < 圆弧 0.414R（更饱满=iPhone 连续圆角特征）。k 值经 1.4/1.6/1.8/2.0/2.5/3.0 视觉对比选定 2.0（k≥2.5 对角出现"尖喙"收紧）
- 教训：超椭圆闭合曲线的象限切线≠贴边圆角所需切线；圆角曲线必须参数化为"起点切向沿来边、终点切向沿去边"

**测试**：TEMP/icon_test.py 32 项全过（边界盒 46²、对角饱满度数值对比、角部起/终点切线斜率 0.021<0.05、渐变/字形/选中态/64px 应用图标像素断言）；titlebar 52 项、冒烟、像素回归全过。截图 TEMP/win_expanded_new.png / win_collapsed_new.png / icon_sheet_new.png

## 低清预览小窗排列优化（第四轮）

**需求**：用户截图——悬停标签卡弹出低清小窗（截图为小窗浮在标签卡下方），"小窗排列不够美观"。

**诊断**（离屏复现 + 截图比对）：截图里视频上方无大预览面板的标题行/控制条 → 主体是悬停小窗 HoverPreview（420×248 固定尺寸）。问题：① 固定尺寸与视频宽高比不匹配→letterbox 暗边；② 无标识（裸视频矩形）；③ 位置相对标签卡左偏 24px，不齐；④ 子控件不受父级圆角裁剪，视频方角戳出圆角框。附带修复了大预览面板的真实 bug：`_PreviewVideoWidget` 原只设 minimumHeight，高度变化不传播 → 面板被滚动区压扁（复现：面板 388 而视频要 546，视频溢出、控制条被挤出生效区）。

**实现**：
- **HoverPreview 重做**：标识栏（品牌圆点+标题超宽省略+「低清」徽章，深色圆角上沿）+ 视频区；整窗按视频宽高比精确伸缩（宽 400 基准，高封顶 460 时收窄宽度，恒无黑边）；`QRegion` 四角四分圆遮罩（r×r 方块 ∩ 2r×2r 椭圆，椭圆心在内侧 (r,r)——曾错写成角点导致遮罩为空）；定位改为与标签卡左边缘对齐、正下方 8px（`place_near` + resizeEvent 里 `_replace_near` 重定位）；`ready` 信号改携标题，`_HOVER_CACHE` 改存 (url, title)；worker 只调一次 `_video_info` 拿标题+cid
- **大预览面板**：视频高度 min/max 同锁（精确宽高比）+ 沿父链 updateGeometry + `_on_video_height_changed` 同步面板 minimumHeight；面板设 `QSizePolicy.Fixed` 纵向策略；工具行拆成模式二选一（在线=链接行/本地=文件行），消除堆叠杂乱；加载占位抬高 240 避免高度跳变
- **空状态**：「暂无下载任务」纯文字 → 虚线圆角占位框（theme.py 新增 `QFrame#emptyState` + emptyTitle/emptyHint 样式）

**测试**：TEMP/verify_hover.py 15 项（尺寸/遮罩含四角抠除/4:3 与 9:16 伸缩/标题省略/对齐定位/底部上翻）、verify_preview.py 12 项、verify_resize.py（7 轮缩放收敛，宽高比恒等）、icon 32 / titlebar 52 / 冒烟 / 像素回归全过

## 悬停小窗孤儿弹窗修复（第五轮）

**需求**：用户截图——"链接消失了 但预览窗口还在"。悬停标签卡弹出低清小窗后，标签卡被移除（点 × 删除/双击恢复/开始入队）或鼠标移开，小窗滞留屏幕成孤儿。

**根因**（三处生命周期断点）：
1. `HoverPreview` 自身无 `leaveEvent`——鼠标经小窗"中转"离开标签卡（350ms 宽限内小窗存活）后，再移开小窗没有任何机制收起它
2. `_remove_tag_card` 不移除小窗——删除/恢复/入队移除标签卡时，小窗锚点成野指针仍显示
3. 切换侧边栏页面/最小化主窗时，置顶 Tool 小窗浮在其他页/桌面上

**实现**：
- `hover_preview.py`：新增 `enterEvent`/`leaveEvent` + 250ms 自隐藏定时器（缓冲期内折回锚点标签则保留，`_self_hide_check` 检测小窗与锚点 `underMouse`）；`_bvid` 跟踪 + `serving(url)` 比对；`show_preview` 加同视频播放中去重（防鼠标在卡上移动导致画面重启）；`hide_preview` 清 `_anchor`/`_bvid`；`_replace_near` 对野锚点 try/except RuntimeError 防御
- `download_page.py`：`_remove_tag_card` 移除前若小窗正在预览该链接则连带退场；新增 `dismiss_hover()`（带 RuntimeError 防御——解释器退出时 C++ 对象可能先销毁，atexit 崩过）；`hideEvent` 调用之
- `main_window.py`：`changeEvent` 最小化分支遍历 `_stack` 调各页 `dismiss_hover`

**测试**：新增 TEMP/verify_orphan.py 29 项全过（删除/双击恢复/批量入队连带退场、移出自隐藏、折回锚点保留、重入取消、页面隐藏退场、重复悬停不重播、野锚点双路径防御、serving 比对）；全回归：hover 15 / preview 12 / resize PASS / icon 32 / titlebar 52 / 冒烟 / 像素。截图 orphan_stateA_hover.png（弹出态）vs orphan_stateB_deleted.png（删标签后小窗退场、页面回空态）

## 开始按钮消失 / 删除图标 / FFmpeg 完整版自动升级（第六轮）

**需求**（用户截图 + 描述）：①"开始按钮消失了"；②删除按钮渲染成豆腐块、没有合适图标；③完整版 ffmpeg 不入 git（仓库带精简版），启动检测到非完整版自动下载、校验可用后替换；精简版期间做不到的选项（如转 wav）禁止选择。

**① 开始按钮消失根因**（像素级截图分析确认）：用户屏 1861×882 物理 = 1240×588 逻辑 @150% DPI；窗口默认 resize(1280,800)+setMinimumSize(1060,680) 换算后 1920×1200 物理，底部约 318px（含滚动区外固定操作条）被裁出屏幕，且最小高度 680 逻辑 > 屏高 588，用户无法缩小窗口 → 操作条永久不可见。截图证据：侧边栏 47px、卡片左右边距 42px（=28 逻辑×1.5）、caption 按钮位置全部与"窗口 x=-49、宽 1920"模型精确吻合。
**修复**：`MainWindow._fit_to_screen()`（__init__ 调用，screen 可注入便于测试）：初始尺寸与最小尺寸收敛到 `screen.availableGeometry()` 并居中；大屏不收缩。

**② 删除图标**：`_DeleteIconButton(QPushButton)` 自绘（仿 _CaptionButton 模式）——48 画布圆头 × 双笔触（DPR=2，24px 显示），常态 `text_faint` 灰、悬停/按下红字 + 红色淡底（alpha 0.10/0.18，圆角 7）。替换 TagCard 的文本 "×" 按钮（U+00D7 在用户字体缺失渲染成豆腐块）。

**③ FFmpeg 完整版管理**（ffmpeg_manager.py 重写）：
- 能力探测：`-encoders/-muxers/-filters` 解析（标志列 1-6 字符 + 第二个 token 为名称），按 (path, mtime, size) 缓存，二进制替换自动失效
- `FORMAT_REQUIREMENTS`：flv→muxer:flv、wav→encoder:pcm_s16le+muxer:wav、mp3→encoder:libmp3lame；`MONO_REQUIREMENTS`→filter:aresample（精简版缺重采样，单声道会降级双声道）；`FULL_MARKERS` 判定完整版
- 精简版实测（833KB ffmpeg 5.1.2）：仅 libmp3lame 编码 + mp4/mp3/mov 封装 → **flv/wav/单声道均不可用**（flv 此前能选但合并必失败，属既存缺陷）
- 自动升级：后台下载（BtbN `releases/latest/download/ffmpeg-master-latest-win64-gpl.zip` 固定资源名免 API，gyan 备用）→ 提取 bin/ffmpeg.exe → 校验 FULL_MARKERS → `os.replace` 原子替换；占用退避重试 45×2s，仍败暂存 `ffmpeg-full.exe` 下次启动补替换；替换后 `git update-index --skip-worktree` 防大文件误提交
- UI 门控：下载页/设置页格式下拉与标签卡右键菜单按能力置灰 + tooltip；单声道置灰；配置默认格式不可用时回退 mp4（`_forced_fallback` 标记，完整版就绪后恢复）；下载页新增 `ffmpegNotice` 提示条（进度/失败重试/精简版说明）；设置页 FFmpeg 状态行 + 手动下载按钮；首页状态卡适配新状态（full/lite/downloading/failed/missing）
- 新增 wav 格式：`_merge_streams(audio_codec=)`（mp3→mp3 / wav→pcm_s16le），音频分支泛化，单声道降级逻辑保留

**测试**（13 套件全过）：verify_ffmpeg 34（真实精简版探测 + 注入完整能力门控翻转 + 缓存失效 + 缺失路径）、verify_fitscreen 15（假屏 1240×588 收敛/居中/操作条在窗内/大屏不缩）、verify_delete_icon 16（三态像素）、verify_gating 27（下载页+设置页门控与解锁）、verify_wav 11（命令构造+降级）、既有 orphan 29/hover 15/preview 12/resize/icon 32/titlebar 52/冒烟/像素
**踩坑**：① `_build_ffmpeg_notice` 忘存 `self.ffmpeg_notice`，被 hasattr 守卫静默吞掉——测试驱动发现；② grab() 把半透明底合成到白底（251,233,233），底色检测需按"红透白"而非 alpha；③ `config_manager` 是模块，实例方法补丁要打在 `ffmpeg_manager.get_ffmpeg_path` 上

## 完整版 ffmpeg 是否入库评估（第七轮·阻塞）

**需求五**：用户追加——"如果 ffmpeg 不大于一百兆，不触发 git 上限，就把 ffmpeg 也放进仓库里作为默认文件，保留启动自检，损坏时可再次自动拉取"。

**实测结论：条件不成立，维持需求四架构**：
